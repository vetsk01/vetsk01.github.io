3. Drafting conventions

  • Every figure is a token ({{fig:C-MET-01}} or {{row:R-001}}). Never type a number into narrative. QA Q05 fails a typed number.
  • Every framework reference is a requirement id in brackets ([S2-MT-a1]) that resolves to a row in a framework file. QA Q14 checks this.
  • Every section opens with a boundary line (who and what it covers).
  • Forward-looking statements carry a hedge (expect, aim, subject to). QA Q06.
  • Voice and anonymisation: ../methodology/narrative-voice-v1.md, ../methodology/anonymisation-convention-v1.md.

4. QA protocol

  • Where checks run: after every engine run, and always before a draft leaves the team. One command: outputs/run-all.sh (or qa/run_qa.py --case <folder>).
  • How they are logged: each run appends a JSON line to qa/qa-log-v1.jsonl with the report's hash, the verdict and each check's status and detail. NA results say why. The log is append-only.
  • What an LP is told when they ask "how do you know this is right?": "Every figure in the report is pulled by script from a data table where each row names its source and a data-quality grade. A QA checklist runs on every version, including that emission factors match one reference version, that no number is typed by hand, and that every framework reference resolves. The log of every run, with the report's fingerprint, is kept. The report is not assured by a third party." (Adjust the last sentence if it is.)

5. Version discipline

  • File names carry -vN. Draft files are edited in place with each edit logged (hash, reason). Once a file has been in a reviewer packet or frozen at sign-off, a change is a new version. Superseded versions go to _archive/; nothing is deleted.
  • The report date is a setting, never typed into a script. A figure's age runs from the end of its period. External reference data carries its vintage and is not flagged as stale for age.
  • Framework files carry a version, a status as of retrieval, and a re-check-by date.
