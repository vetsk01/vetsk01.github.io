How to re-run and update this work

This guide is for whoever at Northwood updates the work next quarter. The short version: replace the data, set a new report date, run the numbered scripts in order, and rebuild the pages. Every script refuses to overwrite a file, so each run goes in its own new folder. The full run order, with what each script reads and writes, follows.

How to re-run and update the Week 4 materiality work (re-run note v18)

What this covers. The five deliverables: the connected dataset (D1), the financial exposure model (D2), the extended data (D3), the materiality matrix (D4) and the initiative ranking with the one-page view (D5), plus the explorer: one page that puts the exposures and the initiatives in one ranked value-creation backlog, with the cost, effort and payback of acting beside the exposure. Version 12 replaced the earlier client deck and portal with the explorer; version 18 adds the revision layer and rebuilds the deck, explorer, exposure model, matrix and initiatives page, data book, re-run guide and portal as one delivery set. Versions 8 and 9 add the ten-company rebuild: all ten portfolio companies run through one protocol (documented inputs for the six companies outside the priority four, an evidence sweep of the data room, the customer carbon-data requirement as rule R12, and the cost of responding to it as a labelled estimate). Version 9 applied the findings of its review and version 10 settles the findings left after it: the company inputs behind the exposure model sit in two tables you edit, not in code; the physical-weather lines follow one set of rules (a loss someone else bore is not the company's, a company that reports no loss is shown as reporting none, an unreported loss is derived only from the company's own files); the sweep reads its recorded judgments and its percentage ranges as ranges; every benchmark behind the cost estimate has its address and the date it was checked; and a held-out check of the sweep's reading is shipped with its labels. Everything is rebuilt by 24 Python scripts run in a fixed order. Nothing needs a Kith tool, a Kith account or a Kith person. You need Python 3 (the delivered run used 3.9.6), the two add-on packages in requirements-v1.txt, openpyxl and xlrd (python3 -m pip install -r requirements-v1.txt; they read Excel files) and your own data room.

The revision layer (steps 23 and 24). After the explorer, the work was revised and finished as one delivery set for the reader at Northwood: all ten companies, the priority four marked, no exposure line left without a figure or a stated reason, one exit timing per company, and one portal. Step 23 writes a new version of the ten-company data layer (connected dataset v4, exposure lines v6, matrix v5, ranking v6) in which gaps are estimated from published benchmarks or from the portfolio's own observed figures, marked grade C, and each estimate is cross-checked in revision-validation-v1.csv. Step 24 builds the client deck, the explorer, the exposure model, the matrix and initiatives page, the data book, the re-run guide and the portal, with copies of the data files. The method for the revision is in charter-v7-addendum-v1.md; every outside figure used is in revision-benchmarks-v1.csv with its source, date and sentence.

What you receive (the full list, with a fingerprint for each file, is handover-list-v17.csv in this folder):

  • requirements-v1.txt, the exact package versions used, and setup-rerun-folder-v3.py, which sets up a fresh folder for a run;
  • the 24 scripts, in my-work/week-4/pipeline/, the two helper modules the evidence sweep imports (sweep_logic_v6.py, sweep_logic_v8.py), the five helper modules the page builders import (w4_model_v1.py, w4_pages_v1.py, w4_content_v1.py, w4_deck_v1.py, w4_process_v1.py), and kit.py, the small helper that stamps each run into a log and refuses to overwrite an existing file;
  • the reference data in my-work/week-4/reference-data/ (EIA prices, FRED rates, FEMA disaster declarations, the IAC energy-saving database), each with its source and download date in the assumptions register;
  • the assumptions in three tables you can open in Excel: assumptions-register-v3.csv (A-01 onward: value, unit, source, date, who owns it, which deliverable uses it, grade A to C) g2-assumptions-v1.csv (the inputs behind the Clearview fleet estimate, labelled as an estimate) and assumptions-register-additions-v7.csv (A-44 and A-45, the day rate and effort days behind the cost-to-respond estimate; step 21 appends them to the register from step 19 to make assumptions-register-v10.csv);

  • the evidence-sweep record the sweep script reads: sweep-commissioning-v7.csv (the tests the sweep logic passed and the fingerprints of that logic) and sweep-judgments-v4.csv (the 42 paragraphs a reviewer has judged; the sweep leaves them out of its queue). The harness that recommissions the sweep logic if you change it is test-sweep-v7.py (with test-sweep-v1.py). The held-out check of the sweep's reading is sweep-holdout-sheet-v1.csv (12 paragraphs), sweep-holdout-key-v1.csv (the script's reading), sweep-holdout-agent-v1.csv (the review agent's blind reading), sweep-holdout-labelled-v1.csv (the labels) and sweep-holdout-score-v1.csv (the comparison) and sweep-qualexist-queue-v1.csv (the twelve paragraphs the qualified-existence rule queued), with build-holdout-batch-v1.py and score-holdout-v1.py to repeat it;

Set up for each run

  1. Keep the received files unchanged in one folder (the received folder): my-work/... at the paths in handover-list-v17.csv, and your data room at data/northwood-capital/.
  1. Run, with your own report date: python3 my-work/week-4/leave-behind/setup-rerun-folder-v3.py <received-folder> <new-folder> --report-date YYYY-MM-DD. Use a new folder for every run (it refuses a non-empty one, and the scripts never overwrite). The setup script copies every file the scripts need, but not the delivered outputs, which stay in the received folder to compare against. It creates the empty output folders, adds the marker file CLAUDE.md (the scripts look for it to find the project root), links your data room, puts the decisions behind the delivered files (id, date, summary, decision and rationale; 129 rows, including the two pre-registration decisions the extended-data script checks) in record/decision-log-v1.csv, and writes the settings file as my-work/week-4/manifest-v1.json.
  1. manifest-v1.json is the only place the report date lives; no script has it typed in. It also holds the input pins: the fingerprint (SHA-256) of every data-room, Week 3 and reference file the work was built on. Step 2 of the run order stops if a pinned file no longer matches. Version 4 of the settings file also pins the data-room files the evidence sweep and the explorer read (including Northwood's firm overview). Use the delivered date only to reproduce the delivered numbers exactly.

Updating next quarter

  1. Data. Replace the data-room files the scripts read (the spine tables portco_kpis.csv and portfolio_companies.csv, the questionnaires, facility locations, supplier file, budgets) and the Week 3 carbon outputs. Each lineage file lists, for every figure, the file, line, period and grade it came from, so you can see what to swap. After swapping a file, update its pin: run shasum -a 256 <file> and put the result in inputs.sources in manifest-v1.json.
  1. Reference data. Download the newer EIA, FRED, FEMA and IAC files into reference-data/, re-pin each (shasum -a 256 <file>, then inputs.sources in manifest-v1.json), edit the typed constants for any FEMA file (see the next section), then update the matching rows in the assumptions register (value, source, source_date, period). External data carries its own vintage; it is not "stale" because it is older than the report date.
  1. Assumptions. For steps 1 to 15, change values in the register, not in the scripts; for steps 16 to 21 see "Updating the ten-company rebuild" below. Items that are judgment, not data, and need an owner's decision each time: the discount rate premium (A-02), hold years N (A-37), exit multiples (A-29), the severity and likelihood bands in the charter, and the Clearview idle-fuel estimate (g2-assumptions-v1.csv, grade C). The ranking is rerun at 8, 10 and 15 percent; a changed premium can change the order.
  1. Periods and dates. Set report_date with the setup script. Remaining hold N depends on it: after step 2 of the run order, compare the N rows in methodology/register-extraction-v5.csv with row A-37 of the register and edit A-37 to match; step 3 stops until they agree (within 0.015). Then work through the typed periods below.
  1. Pre-registration. The extended-data script fixes its random seed and sampling rules in a decision recorded before the data is generated. For a new run, record a new decision and change the two ids and the seed at the top of build-simulated-baseline-v1.py.
  1. Output names. Do not rename outputs. The scripts refuse to overwrite, and later scripts read earlier outputs by fixed name, so every run goes in its own new folder (setup step 2).
  1. Review the explorer's wording. The headline sentences, section titles and notes are typed in build-explorer-v6.py, not generated; the opening sentence and the totals are computed from the book selected. Read the page against the new numbers before it goes anywhere. The builder stops if the company totals it re-sums stop equalling the signed summary, if a cited line no longer carries its words, or if an owner row matches no backlog item.

  1.   1. Still typed in code. Change these, then re-run in order: extract-six-values-v2.py lines 59 to 140 (acquisition dates of the six, and for every exit window and gross margin the file, line and expected text; the acquisition dates are asserted against the company master); build-d4-d5-v4.py from line 103 (the list of company-identified measures for the six: company, file, line, expected text) and the line numbers of Ridgeline's plan table (its figures are read from the file); and the client's severity and likelihood scales (SEV, PRI, BANDS) near the top of build-exposure-model-v5.py and build-d4-d5-v4.py. These are rules and citations, not company results, but they are in code.
  1. EIA price. Step 19 reads the U.S. total commercial price from the "U.S. Total" row of the reference file and states it in the line note and in A-42; it does not compare it with a typed number. It does check that the signed Week 3 energy shock for Sterling, Harvest Ridge and Meridian equals 20 percent of the energy cost in the energy_cost_reported_usd rows; if you replace the Week 3 outputs, update those rows.
  1. Physical-weather rules (A-46). The company's own reported event sets its impact. A loss a property owner bore is not the company's. A combined figure for two events is apportioned by closure days and the combined figure is kept as the upper bound. A company that reports no loss is shown as "reported: no loss", not as a banded zero. An unreported dollar loss is derived only from the company's own cited files (Keystone: cancelled sessions times revenue per session at gross profit), otherwise it is "not quantified". The halve-and-double frequency test runs for every line.
  1. Review queue and judgments. Step 18 leaves out paragraphs already judged in sweep-judgments-v4.csv. A paragraph the logic cannot place appears in sweep-review-queue-v8.csv with its proposed reading. A person reads it and records one row (para_id, answer, direction, value, note, judged_by, judged_date, basis) in a copy of the judgments file saved under a new version name; change the name on the line that reads it in sweep-portfolio-v8.py and re-run. The delivered queue is empty.
  1. If you change the sweep logic (sweep_logic_v6.py or sweep_logic_v8.py) step 18 stops, because the logic's fingerprints no longer match the commissioning record. Run test-sweep-v7.py (it also runs test-sweep-v1.py); first give its output file a new version name, because the scripts never overwrite, then change the commissioning file name in sweep-portfolio-v8.py.
  1. Cost to respond (A-44, A-45, response-cost-inputs-v3.csv, response-cost-components-v1.csv): the day rate and effort ranges are Kith's estimate, graded C. Replace them with your own rates and quotes.

  1. Simulated values. The Harvest Ridge drought curtailment line rests in part on the simulated baseline by a specific exception; replace the simulated values with meter readings and the line becomes measured. The water price line beside it uses the reported volume only.

Checking a run

For the delivered run, handover-list-v17.csv lists a fingerprint (SHA-256) for every received file and every delivered output. A re-run from the same inputs and the same report_date rebuilds all 77 delivered outputs byte for byte; if one differs, an input has changed. To fingerprint a file: shasum -a 256 <file>.

Known issues in the delivered run

  1. Register note A-13 is wrong; the value is right. The note on row A-13 of assumptions-register-v3.csv says the questionnaire-implied Harvest Ridge electricity price is about 15.8 cents per kWh. It should read about 13.5 cents per kWh (the A-19 electricity cost divided by the questionnaire kWh), nearly double the EIA industrial average of 7.13. No model value used 15.8: D5 computes the price from A-19 and the kWh, and the stored EIA ratio of 0.5274 matches 13.5. The register stays as delivered and this entry is the correction.
  1. No IAC cross-check was run at this stage; it was done later in the revision layer, where 2 of 2 company paybacks sit inside the DOE lighting range (solar and HVAC remain untested). The DOE IAC database is in reference-data/ and pinned, and the charter (rule R8) makes it a cross-check only. No cross-check rows were produced: all five quantified measures come from company questionnaires, so none is benchmarked against IAC. Adding that benchmark is a new step, not a fix to an existing one.

02Back-end note: how it was built

Everything in the build is one of six things, and each number has a trail

This note is for whoever audits or maintains the work. It shows what each part of the process does and how the parts link, without opening a single script. Counts are the record as at 11 October 2026, before the final (G7) freeze.

Rules

The charter's 16 rules say what must be true: units, scenarios, bands, missing data, ranking, simulated data and the customer data requirement. Nothing on a page departs from them unless a dated decision says so.

Scripts

24 run-order steps (87 script versions are kept) build every file from the data room and the reference data. They stop with a plain message if an input, header or period no longer matches, and never overwrite.

Checks

Gate checks re-derive figures from source and fail on a defect; each is proved with seeded failures before it is trusted (33 test files). A check that passes is stronger evidence than a reviewer's opinion.

Reviewers

Reviewer agents, each read-only and given one question, work from the same packet: Evidence review, Audience read, Presentation review, Method review, Process review. They raise findings; they cannot change a file.

Decisions

180 decisions are logged with the date and channel, and the owner's words wherever the owner decided. A builder's proposal is marked proposed until the owner ratifies it.

The record

289 entries are linked to one another, so an earlier entry cannot be altered without breaking the chain. 259 journal entries say what was done, why, and what was left open.
